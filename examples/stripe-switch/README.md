# Stripe switch-over sample (DEV-006, partial)

`NectarBillingApp` runs on a merchant backend. Its injected API transport uses an authenticated owner session under the currently adopted conservative default. It never sends a provider key or operator session to a browser. Dedicated app-write credentials and the complete checkout/portal/meter-event switch-over remain unbuilt; this sample is not a complete Stripe SDK replacement.

A product calls `invoicePreview({subscription, account_ref})` with its Nectar subscription id and configured source account. The same call uses Stripe's authenticated preview while the subscription is in shadow, and Nectar's ordinary rating engine after adoption. Before a future cutover it selects the first Nectar-owned period. Amounts are integer cents; this sample does not promise provider-identical response objects. `tests/nectar/stripe-app.mjs` exercises this unchanged method before and after adoption. `tests/nectar/webhook-shadow-sandbox.mjs` repeats the exact 59,700-cent comparison against an owned Stripe test subscription and a separate adopted installation.

For an existing imported seat price, `prepareQuantity` freezes the complete current source items and a proposed positive integer quantity. A human reviews the returned values and calls `confirmChange(id, true)` once. This explicitly authorizes a test-mode Stripe update with no proration. An uncertain response is reconciled by `reconcileChange(id)`, which only GETs Stripe; it never repeats the POST. Pending uncertain writes fence cutover, and the captured request/fence survives an archive restore. Native quantity/price changes continue through the ordinary governed change doors in API.md. Review the full call map there before switching another call.
